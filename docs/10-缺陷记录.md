## BUG-001 双击启动毫无反应：主窗口构造函数里过早导航导致进程静默死亡

**发现方式**：M0 交付后由用户实机双击 `HdcMirror.App.exe`，反馈「没有发生任何事情，托盘也没有变化」。

**症状**
- 双击 exe：无窗口、无托盘图标、无任何提示，进程秒退。
- 事件日志：`Faulting application name: HdcMirror.App.exe` / `Exception code: 0xe0434352` / `Faulting module name: KERNELBASE.dll`。
- `%LOCALAPPDATA%\HdcMirror\` 目录根本没被创建 —— 说明死得比任何日志初始化都早。

**根因**
`MainWindow` 构造函数里在 `InitializeComponent()` 之后立即调用了：
```csharp
RootNavigation.SetPageProviderService(AppPageProvider.Instance);
RootNavigation.Navigate(typeof(DevicesPage), null!);   // ← 崩在这里
```
WPF-UI 的 `NavigationView` 在模板尚未套用（窗口未 `Loaded`）时，内部用于承载页面的 `ContentPresenter` 仍是 `null`。
`Navigate` → `NavigateInternal` → `UpdateContent` 对 null 解引用，抛 `NullReferenceException`：

```
System.NullReferenceException: Object reference not set to an instance of an object.
   at Wpf.Ui.Controls.NavigationView.UpdateContent(Object content, Object dataContext)
   at Wpf.Ui.Controls.NavigationView.NavigateInternal(...)
   at Wpf.Ui.Controls.NavigationView.Navigate(Type pageType, Object dataContext)
   at HdcMirror.App.MainWindow..ctor() in MainWindow.xaml.cs:line 15
   at HdcMirror.App.App.OnStartup(StartupEventArgs e) in App.xaml.cs:line 53
```

这个异常发生在窗口显示之前，且没有任何全局异常处理，于是 WPF 直接把进程带走。用户看到的就是「双击没反应」。

**为什么前一轮没发现**
M0 交付时只做了编译验证 + 无头断言（`_probe\m0verify` 里 18 项断言全过），**没有真正启动过 GUI**（当时的判断是「无头环境会挂住」）。编译通过不等于能启动 —— 这是流程漏洞，不是运气问题。

**修复**
1. `MainWindow.xaml.cs`：构造函数只注册 `SetPageProviderService`，首屏导航改到 `Loaded` 事件里做一次；`NavigateTo` 增加未加载时的延后分支（托盘在首帧前点「基本设置」也不会再踩同一个空引用）。
2. `App.xaml.cs`：新增 `InstallCrashGuard()`，在 `OnStartup` 最开头（任何界面代码之前）挂三类处理器：
   - `DispatcherUnhandledException` → 写日志 + 弹一次说明框 + `Shutdown(1)`
   - `AppDomain.CurrentDomain.UnhandledException` → 写日志
   - `TaskScheduler.UnobservedTaskException` → 写日志
   崩溃日志落 `%LOCALAPPDATA%\HdcMirror\logs\crash-yyyyMMdd-HHmmss.log`，含时间、版本、OS、运行时描述与完整堆栈。
3. 新增三个资源键：`Err_UnhandledTitle`、`Err_UnhandledBody`、`Err_LogFolderOpen`（**界面文案一律走 `Strings`，不许在代码里写中文**）。

**验证**
重新构建后启动，连续观察 8 秒：
- 进程存活，窗口标题稳定为「鸿蒙手机无线控制 · HdcMirror」
- stderr 为空（无未处理异常）
- `logs\` 目录未产生崩溃日志

**流程改进（立即生效）**
> **每个里程碑都必须真的把 GUI 跑起来看一次**，不许只用「编译 0 error + 无头断言」当验收。
> 无头断言能证明「逻辑对」，证明不了「窗口能出来」。后续里程碑验收清单里固定加一条：启动后能截到窗口。

## BUG-002 全解决方案构建撞上并行任务的未完成代码

**症状**
改完 App 层后执行 `dotnet build src\HdcMirror.sln -c Release`，报：
```
HdcMirror.Core\Scrcpy\ScrcpyClient.cs(200,24): error CS1061:
  "GrpcChannel" 未包含 "DisposeAsync" 的定义
```

**根因**
不是代码缺陷 —— 是**并行冲突**。当时 M1 的协议层实现正在同一个 `HdcMirror.Core` 工程里写文件，我构建时正好读到它写到一半的状态。`GrpcChannel` 在 `Grpc.Net.Client` 里只实现了 `IDisposable`，没有 `DisposeAsync`，该文件当时尚未定稿。

**处置**
- 该次只单编 App 工程验证自己的改动：
  `dotnet build src\HdcMirror.App\HdcMirror.App.csproj -c Release -p:BuildProjectReferences=false`
- 纪律：**有专家在改某个工程时，不要去构建整个解决方案**，也不要顺手去"修"别人未完成的文件。等对方交付后再做全量构建。

## BUG-003 用 `edit` 工具改 `.ps1` 会丢 UTF-8 BOM，导致脚本语法崩

**症状**
`tools\pre-push-check.ps1` 经 `edit` 改写后，PowerShell 5.1 报一堆 `Unexpected token '}'`，且脚本里中文全是乱码。

**根因**
文件原是「UTF-8 带 BOM」。`edit` 写回时用无 BOM 的 UTF-8，而 Windows PowerShell 5.1 在无 BOM 时按系统 ANSI（GBK）解码，中文字节被误读，字符串终止符随之断裂。

**修法**
```powershell
$b = [IO.File]::ReadAllBytes($f)
$bom = [byte[]](0xEF,0xBB,0xBF)
[IO.File]::WriteAllBytes($f, $bom + $b)
```
校验：
```powershell
$err=$null
[void][System.Management.Automation.Language.Parser]::ParseFile($f,[ref]$null,[ref]$err)
```

**纪律**：改任何 `.ps1` 之后，必须**先查 BOM、再做语法解析校验**，不许只看"文件保存成功"。
