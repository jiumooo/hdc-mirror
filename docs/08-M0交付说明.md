## 3. 依赖方向的落实证据


`src/HdcMirror.App/HdcMirror.App.csproj`（节选）

```xml
<PropertyGroup>
  <OutputType>WinExe</OutputType>
  <TargetFramework>net8.0-windows</TargetFramework>
  <UseWPF>true</UseWPF>
  <ApplicationIcon>Assets\app.ico</ApplicationIcon>
  <NeutralResourcesLanguage>zh-CN</NeutralResourcesLanguage>
</PropertyGroup>
<ItemGroup>
  <PackageReference Include="WPF-UI" Version="4.3.0" />
  <PackageReference Include="H.NotifyIcon.Wpf" Version="2.3.2" />
</ItemGroup>
<ItemGroup>
  <ProjectReference Include="..\HdcMirror.Core\HdcMirror.Core.csproj" />
  <ProjectReference Include="..\HdcMirror.Decode\HdcMirror.Decode.csproj" />
</ItemGroup>
```

**三条结论都可机械验证：**

1. Core 没有 `UseWPF`、没有 `-windows` 目标、没有任何 `PackageReference` —— 它连 WPF 程序集都拿不到，
   想写 WPF 代码根本编译不过。符合「若 Core 需要 `net8.0-windows` 才能编译，说明依赖方向错了」。
2. Decode 同样没有 `UseWPF` / `-windows`，只引用 Core —— 解码层拿不到 UI，也无法反向依赖 App。
3. App 同时引用 Core 与 Decode；引用方向单向，反向引用会让 `dotnet build` 直接报循环依赖。

自检命令（可重复执行）：

```powershell
Select-String -Path src\HdcMirror.Core\HdcMirror.Core.csproj,src\HdcMirror.Decode\HdcMirror.Decode.csproj -Pattern 'UseWPF|net8.0-windows|PackageReference'
# 期望：无任何输出
```

### 5.2 「XAML / C# 无硬编码中文」的自证

第一步：允许命中的只有注释。原始 grep（含注释）：

```powershell
# ripgrep 等价命令：
#   rg -n --glob '*.xaml' '[\x{4e00}-\x{9fa5}]' src/
Get-ChildItem src -Recurse -Include *.xaml | Select-String -Pattern '[\u4e00-\u9fa5]'
```

结果：`src/HdcMirror.App` 下 16 处命中，**逐条核对全部落在 `<!-- -->` 注释内**
（`App.xaml:9`、`MainWindow.xaml:19/34`、`DevicesPage.xaml:8-12`、`SettingsPage.xaml:8-12`、
`AboutPage.xaml:8-10`），无一条是可见文案。

第二步：**剥掉注释后再查**，这才是「界面文案是否硬编码」的真判据：

```powershell
$files = Get-ChildItem -Path 'src\HdcMirror.Core','src\HdcMirror.Decode','src\HdcMirror.App' -Recurse -Include *.xaml,*.cs |
         Where-Object { $_.FullName -notmatch '\\(obj|bin)\\' }
$bad = 0
foreach ($f in $files) {
  $text = Get-Content -Raw -Encoding UTF8 $f.FullName
  if ($f.Extension -eq '.xaml') {
    $text = [regex]::Replace($text, '<!--.*?-->', '', 'Singleline')
  } else {
    $text = [regex]::Replace($text, '/\*.*?\*/', '', 'Singleline')
    $text = [regex]::Replace($text, '//[^\r\n]*', '')
  }
  if ($text -match '[\u4e00-\u9fa5]') { $bad++ ; Write-Host $f.FullName }
}
"去注释后含中文的文件数 = $bad"
```

结果（实际输出）：

```
文件数 = 18
去注释后含中文的文件数 = 0
```

即：本次三个工程 18 个 `.xaml` / `.cs` 文件，**去掉注释后一个中文字符都不剩**，
所有可见文案都在 `Resources.resx` 里。

第三步：隐私扫描（顺带做的，RULES.md 红线）：

```powershell
Select-String -Path $files.FullName -Pattern '\b192\.168\.|\b172\.(1[6-9]|2[0-9]|3[01])\.|\b10\.[0-9]+\.[0-9]+\.[0-9]+|C:\\Users\\'
```

结果：**0 处命中**。源码里没有任何私网 IP、设备地址、本机用户目录写死。

## 8. 遇到的问题与解决（含 WPF-UI / H.NotifyIcon 的坑）

### 8.1 `H.NotifyIcon.Wpf` 2.4.1 无法用于 net8（NU1701）

```
error NU1701: 已使用“.NETFramework,Version=v4.6.1...”而不是项目目标框架“net8.0-windows7.0”还原包“H.NotifyIcon.Wpf 2.4.1”
```

原因：2.4.1 只发布 `net10.0-windows7.0` 与 `net462` 两个目标，net8 项目会落到 .NET Framework 资产上。
处理：**降到 2.3.2**（`lib/` 下有 `net462`、`net8.0-windows7.0`、`net9.0-windows7.0`），restore 通过。
写法上不必用 XAML 资源：代码里 `new TaskbarIcon { IconSource = ..., ContextMenu = ... }` +
`ForceCreate(false)` 即可，`ForceCreate` 的布尔参数是「是否开启 Efficiency Mode」，托盘需要随时响应单击，故传 `false`。

### 8.2 `Wpf.Ui.Controls` 与 `System.Windows.Controls` 的名字冲突（CS0104）

首次构建失败：

```
App.xaml.cs(98,20): error CS0104: “MenuItem”是“Wpf.Ui.Controls.MenuItem”和“System.Windows.Controls.MenuItem”之间的不明确的引用
```

原因：为拿 `WindowBackdropType` 写了 `using Wpf.Ui.Controls;`，而该命名空间也定义了 `MenuItem`（WPF-UI 自己的菜单项控件）。
处理：删掉整体 using，改成**单类型别名**

```csharp
using WindowBackdropType = Wpf.Ui.Controls.WindowBackdropType;
```

`ContextMenu` / `MenuItem` / `Separator` 全部走 `System.Windows.Controls`，语义与托盘菜单一致。

### 8.3 `WPF-UI` 版本与 `ui:` 命名空间

- 包名是 `WPF-UI`（不是 `Wpf.Ui`），版本 **4.3.0**；XAML 命名空间 `http://schemas.lepo.co/wpfui/2022/xaml`。
- `NavigationView` 不能自己造页面：必须给一个 `INavigationViewPageProvider`（`Wpf.Ui.Abstractions`，
  随 WPF-UI 传递引用），否则首屏空白。因此加了 `AppPageProvider`（按 `Type` 反射建页），
  在 `MainWindow` 构造里 `SetPageProviderService` 后 `Navigate(typeof(DevicesPage), null!)` 预选第一项。
- 主题字典用 `Wpf.Ui.Markup.ThemesDictionary` + `ControlsDictionary`；运行期深浅色切换交给
  `SystemThemeWatcher.Watch(window, WindowBackdropType.Mica, true)`，不需要自己监听注册表。

### 8.4 本机 `pwsh` 是 Windows PowerShell 5.1，加载不了 net8 程序集

想用 `Add-Type -Path` 反射加载 `HdcMirror.Core.dll` 做验证，结果 `GetTypes()` 抛
「无法加载一个或多个请求的类型」且 `LoaderExceptions` 为空 —— 因为宿主是
`PowerShell 5.1 / .NET Framework 4.8`，无法加载 net8.0 程序集。
处理：改为在 `_probe/` 下建**不属于解决方案**的临时控制台工程（`net8.0-windows` + `UseWPF`），
用 `dotnet run` 在 .NET 8 运行时里跑断言。它在 `src/` 之外、也不在 `.sln` 内，
`dotnet build src\HdcMirror.sln` 不受影响；编译产物与临时目录验证完已删除。

### 8.5 WPF SDK 的隐式 using 不含 `System.IO`

验证工程里用 `Path` / `File` / `Directory` 报 CS0103，`Microsoft.NET.Sdk` 的隐式 using 在
`UseWPF=true` 下不包含 `System.IO`；补 `using System.IO;` 即可。
主工程三个项目没有触发该问题（Core/Decode 用 SDK 默认集合，App 侧未直接用 IO）。

### 8.6 图标是程序内生成的，没有下载任何外部图片

用 `System.Drawing`（`Add-Type -AssemblyName System.Drawing`）绘制圆角方块 `#0F6CBD` + 白色
Segoe UI Bold「M」，按 PNG 帧格式打包成单文件多尺寸 ICO（16/32/48），落到 `Assets/app.ico`（1858 B）。
用 `New-Object System.Drawing.Icon($path,16,16)` 等三档尺寸回读校验，均能正确解析。
该 ico 同时用于 `<ApplicationIcon>`（exe 图标）与 `<Resource>`（托盘 / 标题栏运行时加载）。
