## 一、布局骨架

主窗口 470×960 起（可拉伸，最小 400×720），自上而下三行，**不再有状态栏**：

```
┌──────────────────────────────────────┐
│ ① 标题栏：菜单 + 窗口按钮（同高 30px） │
├──────────────────────────────────────┤
│ ② 设备栏：扫描 / 设备 / 刷新 / 连接    │
├──────────────────────────────────────┤
│ ③ 内容区：手机屏 或 设置页             │
└──────────────────────────────────────┘
```

- **① 标题栏**：左侧 `HdcMirror │ 设置 │ 帮助`，右侧 `─ □ ✕`。菜单与按钮同一条 30px 基线，左起第一个字距窗口左边 18px、上边 18px。
- **② 设备栏**：控件统一 32px 高（可编辑下拉 34px，矮了会切字）。列固定为 `扫描 | 设备下拉 | 刷新 | 连接`，四周 18px 边距。
- **③ 内容区**：默认显示手机屏（按 `1260:2720` 比例，圆角 30，无外框）；进设置页时就地替换内容，不弹新窗口。

### 启动落位

桌面按宽度五等分，窗口**贴第 4 列**（`Left = 工作区左 + 列宽×3`，宽度取一列，高取工作区高），不再居中。

### 四个设置页

## 四、关键交互规则

1. **改动即存**：所有设置项改动立刻写 `settings.json`，不设「应用」按钮。
2. **不弹新窗口**：设置页在内容区就地显示；只有「支持作者」用独立对话框。
3. **状态不常驻**：临时提示写进手机屏中央的提示层，3 秒自动消失，不长期压住画面。
4. **失败要说清落点**：拖文件进手机失败时回退 `/data/local/tmp` 并显示实际位置，不静默失败。
5. **未实现的功能隐藏而不是置灰**（菜单项、托盘项同此规则）。
6. **滚动区必须能滚到底**：页根底部留白 168px，保证最后一张卡片不被左下缩略屏压住。

## 八、帧率档位（2026-11-12 补）

- 默认档是**自动**：手机当前多少刷新率就下发多少（真机实测当前 60 Hz，支持 120 / 90 / 60 / 30），读不到按 60 兜底。
- 手动档以 **30 为一档**，上限取设备支持的最高刷新率：支持 120 → `30 / 60 / 90 / 120`；只支持 60 → `30 / 60`。
- 档位来源是 `hidumper -s RenderService -a screen` 的 `supportedMode[n]` 与 `activeMode`，解析在 `HdcMirror.Core\Hdc\HdcDeviceInfoReader.ParseRefreshRates`，缓存于 `HdcMirror.App\Services\DisplayModes`。
- 设置页在「自动」右侧显示真机能力（「你的手机：当前 60 Hz，支持 30/60/90/120 Hz。」）；没连过设备时打开该页也会用记住的地址读一次，仍读不到就如实说「尚未读到手机刷新率」。
- 镜像窗口左下角常驻 `无线 · 60 fps`（有线则为 `有线`）——连接方式来自 `HdcDevice.Kind`，帧率来自每秒统计的解码帧数。
## 九、关于帧率与画质（2026-11-12 实测结论）

**帧率为什么到不了手机的 60/90**
- 我们只做两件事：把 `-frameRate` 这个**上限**告诉手机侧守护进程，然后在收到帧时解码显示。
- 实测（`docs\shots` 之外的运行日志）：请求 90 Hz 时，解码平均只要 4~6 ms（相当于 150 fps 的解码能力），但码流实际只送到 25~33 fps，偶尔尖峰 59.7 fps。
- 结论：上限不在客户端。手机侧采集/编码按内容与码率出帧，画面变化少时就是二三十帧；这不是"帧率不同步"，而是手机只推了这么多帧。想提高实际帧率，只有提高码率上限或让画面持续变化。

**画质百分比是怎么实现的**
- 手机原生分辨率始终不变（`-scale 1`）。实测华为守护进程的 `-scale` **只接受 1**：传 `0.5`、`2`、`50` 都起不来（守护进程无 socket、连接超时），所以编码端无法降分辨率。
- 画质百分比 = **码率比例**：`100%` 用设置里的码率上限，`50%` 即上限的一半，依此类推（下限 1 Mbps）。
- 因此"画质和手机一样吗"的准确答案是：分辨率和手机一致，但经过 H.264 压缩，细节不是逐像素一致；100% 时是当前参数下的最好画质，降档换带宽与稳定性。
## 十、清晰度与流畅度预设（2026-11-12）

在「画质」卡片顶部新增一档总开关，选它就等于一次改三项；反过来手动改三项中的任意一项，它会自动跳到「自定义」。

| 预设 | 画质 | 码率 | 帧率上限 |
| --- | --- | --- | --- |
| 清晰优先（默认） | 100% | 24 Mbps | 自动（跟随手机） |
| 均衡 | 50% | 16 Mbps | 自动（跟随手机） |
| 流畅优先 | 33% | 8 Mbps | 30 Hz |
| 自定义 | 手动改任一项后自动落到这里 | — | — |

- 三项目标值集中写在 `src\HdcMirror.App\Views\AvPage.xaml.cs` 的 `Presets` 数组里，顺序必须与下拉项一致。
- 判定是"精确匹配"：三项都对上才算某个预设，否则一律显示「自定义」，不会出现"看起来像清晰优先其实码率不是 24"的假象。
- 选「自定义」本身不覆盖用户已调好的数值，它只是展示态。
- 所有改动即时存盘，下一次连接生效。

## 十一、控件尺寸规范（2026-11-12 定，防「字被切一半」）

**根因**：给 `TextBox` / `ComboBox` 写死 `Height`。WPF-UI 的输入控件模板内部有额外内边距与底边线，`Height=30/32` 时 13px 汉字的下缘会被裁掉（用户截图为证：设备页 IP / 端口框、音画页「超清」「自动」下拉、按键映射「手势」「动作」）。

**规范（唯一标准）**：

| 类别 | 写法 | 值 |
| --- | --- | --- |
| 单行输入（TextBox / ComboBox） | `MinHeight` + `VerticalContentAlignment="Center"`，**禁止写 Height** | **36** |
| 同行按钮（与输入框并排） | `MinHeight` | **36** |
| 独立按钮 / 对话框按钮 | `MinHeight` | **32** |
| 次级小按钮（行内「忘记」「删除」） | `MinHeight` | **32**，`FontSize=12` |
| 页签按钮（设备管理 / 通用设置…） | `MinHeight` | **32**，`FontSize=12` |
| 图标按钮（控制条、标题栏） | `MinHeight` | **30~32**，与所在条高度一致 |

**禁止**：`Height` 用在任何承载文字的控件上；`MaxHeight` 用在文字块上。文字块需要限制行数时用 `TextTrimming` + `MaxLines`（WPF 用 `TextBlock.MaxHeight` 会裁字，改用 `TextWrapping` + 容器约束）。

**同一行必须等高**：设备栏（扫描 / 下拉 / 刷新 / 连接）全部 36；手填地址行（IP / 端口 / 连接）全部 36。

**验收方式**：UIA 读 `BoundingRectangle.Height` 与截图双重确认；`git grep -n 'Height="3[02]"'` 只应命中图标按钮。
