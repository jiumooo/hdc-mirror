## 1. 硬约束（不可协商的技术边界）

这些不是设计选择，是已核实的物理/授权边界。任何功能设计必须在此约束内成立。

| ID | 约束 | 依据 |
|---|---|---|
| **C1** | 手机零安装 ⇒ 屏幕采集**只能**复用华为 `libscreen_casting.z.so`，由 PC 端推送到 `/data/local/tmp` 后用 `hdc shell uitest start-daemon` 拉起 | 自研采集必须写 HAP 装机；且设备侧 XPM 有签名校验，自研 `.so` 塞进去加载不了 |
| **C2** | 「手机控制中心可选输出对象 + 选中电脑后手机静音」**只能**用蓝牙 A2DP Sink 实现 | 内录只是复制音频，不注册成系统音频设备，手机照常外放；第三方无法改系统音频路由 |
| **C3** | `hdc` 是 PC ↔ 手机的唯一通道（无线调试 / TCP） | 用户要求手机零安装 |
| **C4** | 不做代码签名 | 用户明确「签名无所谓，只要用户放行安装就行」 |
| **C5** | 上游那套 `hosScrcpy-*.jar` 自包含 grpc/netty/protobuf，**运行期不能再引入同类依赖**；混淆类 `toString()` 会抛异常，日志禁止拼接消息对象 | 上游 M0 实证；本项目自研 gRPC 客户端可绕开，但协议必须严格对齐 |
| **C6** | 华为固件加强 XPM 管控后，旧 so 变体可能加载失败 → 投屏零帧，客户端无法自救 | 上游 v1.0.2 CHANGELOG 实证；属继承风险，需在「关于」页提示 |

## 2. 功能需求清单

优先级：**P0** = 没有它软件不可用；**P1** = 核心体验；**P2** = 增强。

| ID | 需求 | 验收标准 | 优先级 |
|---|---|---|---|
| **F-01** | 修复「连接成功后调整窗口大小闪退」 | 连接状态下连续拖动窗口边缘改变尺寸 50 次，进程零崩溃；日志无 `hs_err_pid`；画布尺寸变化时画面不撕裂、不黑屏 | P0 |
| **F-02** | 鼠标滚轮 → 手机上下滑动；鼠标右键 → 手机返回 | 滚轮上/下在手机端各产生一次连续滑动手势（非离散滚轮事件），任意鸿蒙应用可滚动列表；右键单击 = 返回键（键码 2），右键长按不触发 | P0 |
| **F-03** | 主窗口 UI 重设计（Win11 Fluent 风格），重排模拟功能键 | 见 §3 UI 规范；功能键（返回/Home/最近任务/音量/电源）位置可拖动或可配置；界面在 100%/125%/150% 缩放下无错位 | P1 |
| **F-04** | 窗口按手机横竖屏状态自动切换 | 手机旋转 90° 后 1 秒内窗口宽高比自动跟随；旋转过程中不崩溃、不丢帧；横屏时功能键自动改横排布局 | P1 |
| **F-05** | 连接窗口 UI 重设计 + 系统托盘 + 右键菜单 | 连接窗口见 §3；托盘图标常驻，右键菜单至少含「基本设置」「完全退出」；关闭主窗口不退出进程（最小化到托盘），「完全退出」才结束进程并释放 hdc/蓝牙占用 | P0 |
| **F-06** | 断线自动重连 | 手机侧 UNAVAILABLE 断开（上游实测约 9 分钟一次）后自动重连，重连成功 ≤ 5 s，期间 UI 显示「重连中(第 N 次)」；连续失败 5 次转为手动重试并给出原因；网络断开/恢复后能自愈 | P0 |
| **F-07** | 优化画面显示速度与连接动画 | 首帧显示时间 ≤ 1.5 s（上游约 10 s）；画面变化到屏幕呈现的端到端延迟 ≤ 150 ms（同 WiFi 5G）；连接过程有明确进度动画（连接设备 → 拉起投屏 → 等待首帧 → 完成） | P1 |
| **F-08** | 优化电脑输入，优先使用手机自带输入法（参考华为超级终端） | 中文输入时，PC 键盘按键转为**向手机输入法注入字母/拼音**，由手机输入法自己上屏（PC 侧不弹候选）；PC 侧仅作透明的按键转发；特殊键（Ctrl/Alt/Win/多媒体键）可映射；已映射字符直接注入，未映射走 `uitest uiInput inputText` 兜底 | P1 |
| **F-09** | 音频同步到电脑，且手机不出声（核心） | 见 §4 详细设计。达成：手机下拉控制中心「音频输出」列表中出现「本电脑」；选中后手机扬声器静音、声音从 PC 播放；可随时切回手机扬声器 | **P0** |
| **F-10** | 画质参数可配置 + 按电脑屏幕比例适配全屏 | 可配置：码率（1~50 Mbps）、帧率（15/30/60）、I 帧间隔、缩放比例、编码质量档；显示模式三档：**等比留黑边 / 裁切填满 / 拉伸变形**；一键全屏（F11）+ 记住上次模式 | P1 |
| **F-11** | 应用内检测更新 + 一键更新（GitHub Releases） | 启动时静默检测 `api.github.com/repos/<owner>/<repo>/releases/latest`；有新版本弹非模态提示（含版本号与更新说明）；点「更新」→ 下载 → 自动安装 → 自动重启，用户只需点一次「允许」；支持跳过此版本；检测失败静默不打扰 | P1 |
| **F-12** | **自适应音画同步**（用户新增） | 见 §5 状态机。空闲或正在出声 → 音画同步；用户操作中 → 操作跟手（视频零缓冲）；状态切换平滑，不出现跳帧/卡顿 | P1 |

## 3. UI 设计规范（Windows 11 Fluent 风格）

### 3.1 视觉基调

| 元素 | 规范 |
|---|---|
| 背景 | Mica 材质（主窗口）；Acrylic（连接窗口/弹出面板）；托盘菜单用系统默认 |
| 圆角 | 窗口 8 px；卡片 8 px；按钮 4 px；输入框 4 px |
| 间距 | 4 / 8 / 16 / 24 四档，禁止随意值 |
| 字体 | `Segoe UI Variable`（跟随系统），正文 14 px，标题 20/28 px，说明 12 px |

| 图标 | Fluent 图标（Segoe Fluent Icons），线性风格 |
| 动效 | 页面切换 200 ms 缓动；按钮 hover 快速反馈；禁止超过 300 ms 的动画 |

## 4. F-09 音频详细设计

### 4.1 方案：PC 端内建蓝牙 A2DP Sink

| 环节 | 实现 |
|---|---|
| 设备发现 | 枚举已配对的蓝牙设备，筛出手机（`BluetoothDevice` + A2DP Sink 能力） |
| 注册为音频接收端 | Windows `Windows.Media.Audio.AudioPlaybackConnection`（WinRT，`AudioPlaybackConnection.TryCreateFromId` + `Open()`） |
| 手机侧呈现 | 手机下拉控制中心「音频输出」出现本电脑名称；选中即把媒体音频路由到 PC，手机扬声器静音 |
| PC 侧播放 | A2DP 流由 Windows 音频栈直接送默认播放设备（无需自己解码） |
| 断开 | `Close()`，手机自动切回扬声器 |

### 4.2 交互流程

1. 首次使用 → 设置页「音频」→「配对新设备」→ 引导用户手机蓝牙搜索本机并配对（一次性）
2. 连接投屏时，若「启用蓝牙音频输出」为开 → 自动 `Open()` 该设备的 AudioPlaybackConnection
3. 状态栏显示「音频：已接管（手机静音）」/「音频：手机外放」
4. 用户随时可在手机上切回扬声器，软件检测到后更新状态，不强行抢回

### 4.3 已知代价（必须在「关于」页如实写明）

| 代价 | 数值 | 处置 |
|---|---|---|
| 音频延迟 | 200~300 ms（SBC 编码，系统级） | 由 F-12 自适应策略吸收；同时给手动滑块 |
| 通话/铃声不走 PC | 协议边界 | 文档说明 |
| 与 2.4G WiFi 互扰 | 明显 | 启动时检测 WiFi 频段，2.4G 时提示「建议切 5GHz」 |
| 一次只能接管一台手机 | A2DP 限制 | 多设备场景给出提示 |
| 需要蓝牙适配器 | 硬件前提 | 无蓝牙时该功能降级隐藏，不影响投屏 |

## 5. F-12 自适应音画同步详细设计

### 5.1 状态机

| 状态 | 进入条件 | 视频缓冲 | 目标 |
|---|---|---|---|
| `Interacting` | 最近 **400 ms** 内收到任意本地输入事件（键/鼠/滚轮/触摸） | **0 ms** | 操作跟手，延迟最小 |
| `Playing` | 蓝牙音频流持续有数据包 **> 300 ms**，且 `Interacting` 已退出 | `audioLatency - videoLatency`（默认 250 ms，可调 100~400） | 音画同步 |
| `Idle` | 无输入、无音频 | 0 ms | 省资源、跟手 |

优先级：`Interacting` > `Playing` > `Idle`。用户一动，立刻退出 `Playing`。

### 5.2 切换平滑策略

- `Interacting → Playing`：目标缓冲从 0 涨到 250 ms，采用「**只丢弃延迟累积、不补帧**」的方式——把 250 ms 内的帧排进队列一次性消化，画面短暂减速 200 ms，不跳帧、不黑屏
- `Playing → Interacting`：立即清空视频队列到最新帧（表现为一次轻微跳帧，用户正在操作时不可感知）
- 状态切换加 200 ms 滞回（hysteresis），避免输入抖动导致状态反复横跳

### 5.3 音频延迟测量

- 首次配对时播放一段 1 kHz 短脉冲 + 记录 RTT，得出近似 `audioLatency`
- 之后每次连接用首包时间戳校准
- 测不准时以手动滑块值为准（设置里给「自动/手动」开关）

### 5.4 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| A2DP 无全局延迟保证 | 不同手机/编码器差异大 | 提供滑块 + 自动测量，不承诺固定值 |
| 频繁切换可能被感知 | 边看边操作场景 | 滞回 + 最短停留时间 500 ms |
| 视频队列增长导致内存 | 长时 `Playing` | 队列上限 30 帧，超出丢最旧帧 |

## 6. 技术架构

### 6.1 分层

```
┌───────────────────────────── 表现层（WPF + Fluent）──────────────┐
│ 主窗口 / 连接窗口 / 设置页 / 托盘 / 通知                          │
├───────────────────────────── 应用层 ─────────────────────────────┤
│ SessionManager（会话与重连）· SettingsStore · UpdateService       │
├──────────┬──────────┬──────────┬──────────┬──────────┬──────────┤
│ Hdc 层   │ 协议层   │ 解码渲染 │ 输入层   │ 音频层   │ 诊断层   │
│ 设备发现 │ gRPC     │ FFmpeg   │ uitest   │ A2DP     │ 日志     │
│ 端口转发 │ H.264    │ D3D 呈现 │ uinput   │ Sink     │ 事件采集 │
│ shell    │ 帧组装   │ 音画同步 │ 键位映射 │ 延迟测量 │ 导出     │
└──────────┴──────────┴──────────┴──────────┴──────────┴──────────┘
```

### 6.2 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 运行时 | **.NET 8**（LTS） | 已装 6.0，需补 8.0 SDK |
| UI | **WPF + WPF-UI（Fluent 2 主题库）** | Win11 原生观感（Mica/圆角/NavigationView），无需 VS 2022 |
| gRPC | `Grpc.Net.Client` + `Grpc.Tools` | 自己实现客户端，摆脱混淆 jar |
| 解码 | `FFmpeg.AutoGen`（DXVA2/D3D11VA 硬解） | 与上游同源（FFmpeg 7.1） |
| 渲染 | `D3DImage` / `WriteableBitmap` + VSync 调度 | 低延迟 |
| 蓝牙 | `Windows.Devices.Enumeration` + `Windows.Media.AudioPlaybackConnection` | 系统级 A2DP Sink |
| 打包 | **Velopack**（`vpk`） | GitHub Releases 直连、增量更新、一键静默安装 |
| 日志 | `Serilog`（滚动文件 + 内存环形缓冲） | 诊断导出 |
| 测试 | xUnit + 回放样本（上游 `sample1.h264` 可作 golden） | 解码回归 |

### 6.3 设备侧启动流程（自研复刻，参考上游）

```
1. hdc list targets                          → 发现设备
2. hdc file send libscreen_casting.z.so /data/local/tmp/
3. hdc shell uitest start-daemon singleness \
     --extension-name libscreen_casting.z.so \
     -scale 1 -frameRate 30 -bitRate 8388608 -p 5000 -iFrameInterval 2000 &
4. hdc fport tcp:<本地端口> localabstract:scrcpy_grpc_socket
     （uitest < 6.0.2.1 时改 tcp:5000）
5. gRPC onStart(Empty) → 收 ReplyMessage 流 → Annex B H.264
6. 输入：TCP 8012 JSON-RPC（module=com.ohos.devicetest.hypiumApiHelper, method=Gestures）
   按键：hdc shell uinput -K -d N -u N
```

## 附录 A：上游实现要点（已核实事实）

**仓库**：`taxiao213/hnscrcpy`，Java 17 / JavaFX 21.0.4 / FFmpeg 7.1-1.5.11（JavaCPP），Apache-2.0，最新 v1.0.3（2026-10-25），单作者，issue 无人回复。

**它本质是华为 `hosScrcpy-1.0.20-beta.jar`（18.86MB）的 JavaFX 外壳**：jar 把 `libscreen_casting.z.so` 推到 `/data/local/tmp/`，用 `uitest start-daemon singleness --extension-name libscreen_casting.z.so -scale 1 -frameRate 30 -bitRate 8388608 -p 5000 -iFrameInterval 2000 &` 拉起；gRPC 走 `hdc fport tcp:<D> localabstract:scrcpy_grpc_socket`。

**proto 只有 3 个 RPC**：`onStart(Empty) returns (stream ReplyMessage)`（唯一视频流）、`onEnd`、`onRequestIDRFrame`。**整条链路没有任何音频接口**——这是 C2 的根因。

**视频格式**：Annex B H.264，4 字节起始码 `00 00 00 01`，每个 gRPC 消息 = 一帧，首消息是 SPS+PPS 合包（33 字节）；**按屏幕变化推流**（静态画面不发帧，静置 7 秒无帧属正常，不可当断流）；交互时 30 fps；实测吞吐约 0.3 Mbps；约 9 分钟被设备侧 `UNAVAILABLE` 断开需重连（F-06 要解决的正是它）。

**输入通道**：触摸/滑动/滚轮走 uitest agent 裸 TCP JSON-RPC（设备端口 8012）：
```json
{"module":"com.ohos.devicetest.hypiumApiHelper","method":"Gestures",
 "params":{"api":"touchDown","args":{"x":600,"y":2000}}}
```
api 取值：`touchDown` / `touchMove` / `touchUp` / `ButtonLeftDown` / `MouseMove` / `AxisUp` 等。**同步 RPC，高频 move 必须节流**。
按键走子进程 `hdc shell uinput -K -d N -u N`。

**真机标定键码**（上游 `scripts/spike-keymap.sh` 实测，官方文档有多处是错的）：
最近任务 `2720`（APPSELECT；`2210`/`187` 无效）、Home `1`、Back `2`、电源 `18`、音量−/＋ `16`/`17`、空格 `2050`（非文档值 2052）、方向键 `2012-2015`（文档猜的 `2071-2074` 全错）、TAB `2049`、ENTER `2054`、DEL `2055`、数字 `2000-2009`、字母 `2017-2042`、Shift `2047`。多段可组合：`uinput -K -d 2047 -d 2017 -u 2017 -u 2047` → 'A'。中文/未映射字符走 `uitest uiInput inputText <x> <y> '<text>'`。
