# 手机音频走电脑播放：参考项目与本次采纳的修正

> 结论先行：Windows 上「手机 → 电脑」这条路只有一个官方通道 ——
> `Windows.Media.Audio.AudioPlaybackConnection`（A2DP Sink，Win10 2004 / 10.0.19041 起）。
> 下面这些项目全都在用它，差别只在封装、重连与 UI。我们要的东西不用换技术路线，照它们的坑改就行。

## 二、它们的共识（也就是我们原来做错的地方）

1. **`StartAsync()` 必须在 `OpenAsync()` 之前 await 完成。**
   `StartAsync` 才是「把本机登记成可接收音频的端点」那一步。我们原来调的是同步 `Start()`（异步登记还没落地就去 Open），
   表现就是手机控制中心「投射音频」里时有时无 —— 正是你遇到的「配对一次之后手机就看不到电脑」。
2. **`OpenAsync()` 失败不抛异常**，而是返回 `AudioPlaybackConnectionOpenResult`，要检查 `result.Status`：
   - `Success` → 真的连上了；
   - `RequestTimedOut` → 手机没点「投射音频」（可重试）；
   - `DeniedBySystem` → 系统/蓝牙栈拒绝，**重试无意义**，必须去蓝牙设置处理；
   - `UnknownFailure` → 未知失败（可重试）。
   我们原来没看 `Status` 就报「已连接」，等于把没连上当成了连上。
3. **`TryCreateFromId` 要在 MTA 线程上调**（AkiLink 注释：STA/WPF 线程调会踩 WinRT 互操作的 `AccessViolationException`）。
4. **不要同时存在多个 `AudioPlaybackConnection` 对象**：重试/自动重连叠在一起会把蓝牙栈搞乱，进而触发重连风暴。
   要么先 `Dispose` 旧的再建新的，要么整进程重开（我们选的是后者：音频跑独立子进程，天然满足）。
5. **`StateChanged` 事件**才是判断「已连 / 断开」的正道，不要靠读文本输出猜。
6. **`DeniedBySystem` 是永久的**，界面该提示去蓝牙设置，而不是无限重试。

## 三、本次按参考实现改了什么

- `src\HdcMirror.Audio\Program.cs`
  - `connection.Start()` → `await connection.StartAsync().AsTask()`，失败只记 `LOG` 不中断；
  - `OpenAsync()` 的返回值改为检查 `result.Status`，分别输出
    `OPENED` / `ERROR 0x8007001F 请求超时：手机没接受投射` / `DENIED 系统拒绝（检查蓝牙配对与驱动）` / `ERROR ...`；
  - `StateChanged` 在 Start 之前订阅，避免漏掉第一次状态迁移。
- `src\HdcMirror.App\Audio\AudioSinkHost.cs`
  - 新增对 `DENIED `（终态失败）与 `LOG `（仅记录）两类行的解析；`ERROR` 仍按可重试失败处理。
- 结论：**技术路线不变**（继续用 `AudioPlaybackConnection` + 独立子进程），改动集中在调用顺序与结果判定。
